# 拾词高考英语 · 文章化背词功能方案

> 版本：v1.0 · 状态：方案已确认，核心功能实现中
> 用户原话：「背词的这个功能过于单一，没有提升用户体验和粘性，我们可以实现文章化背词功能，让这个词汇的背词单元融入文章中，这是一个大功能，我们先计划一下然后实现这个核心功能。」
> 短文来源：**运行时接大模型生成**（用户已确认）

---

## 一、为什么要做

现有背词单元的形态是「一个词 + 一道选择题」。它解决了**识记**，但没有解决**迁移**：

| 现状痛点 | 文章化背词如何回应 |
| --- | --- |
| 单词在词卡里认识，回到阅读里认不出 | 目标词放进连贯短文，先通读再判断 |
| 熟词僻义靠死记中文释义，缺少语境钩子 | 语境决定义项，答案必须由上下文推出 |
| 每日任务是一道道孤立题，缺少完成故事 | 一篇短文串起 3–5 个待复习词，有始有终 |
| 背完就忘，复习动力靠自律 | 到期词 / 高危词直接变成下一篇的选词输入 |

**产品目标**：把「今天该背哪些词」转换成「今天读哪篇短文」，在不增加新记忆系统的前提下，提升单次学习的语境密度与完成感。

---

## 二、核心学习循环

```
① 选文输入          ② 通读               ③ 语境填词
到期词 / 薄弱词  →  短文 + 中文大意  →  挖空处选词/选义
（FSRS 派生）         （先看整体语境）      （必须用上下文判断）

④ 三档自评          ⑤ FSRS 回流          ⑥ 下一篇推荐
认识/犹豫/忘了  →  复用现有 sense 卡  →  按新的到期与高危状态生成
                    与词形网卡片
```

关键约束：

1. **不另起记忆系统**：所有作答都写回现有 `Store.cards` / `Store.families` / `quickPractice`，与词卡模式共享同一份记忆状态。
2. **复用 `sense_id`**：生成结果里每个空必须绑定词库中的义项 ID；绑定失败的空只能走轻量词回流，不写义项卡。
3. **本期不新增付费点**：文章化背词是留存功能，对所有用户（含游客）开放。¥9.9 全包已有的「深度分析」会自然覆盖文章化学习的统计，不额外设墙。

---

## 三、选词策略（输入）

`Article.pickWords()` 从真实学习状态取词，优先级：

1. `Store.reviewForecast().due` 的到期词；
2. `Store.reviewForecast().risk` 的高危词；
3. `Store.wrongWordStats()` 中近期错词；
4. 兜底：词库中已学但稳固度最低的词；新用户取主题高频词。

每篇取 **3–5 词**，尽量同主题（复用 `CTX_BOOK` 的 `theme` 字段），保证短文连贯。若目标词在 `CTX_BOOK` 中有例句，则把例句作为生成锚点传给模型。

---

## 四、模型生成协议（输出）

### 4.1 调用规范

- 客户端：`WorkBuddyCloud` SDK（应用已有实例，从 `cloud.js` 暴露）。
- 模型：`cloud.llm.models.list()` 取第一个 `disabled !== true` 的可用模型。
- 调用：`cloud.llm.chat.completions.create({ model, messages, stream: true, temperature: 0.7 })`。
- **必须 `stream: true`**，逐块收集 `chunk.choices[0].delta.content` 后拼成完整 JSON。
- **首条消息必须是应用自管的 `system`**，不放用户输入。
- 一次性生成不传 `conversationId`。
- 无可用模型 / 调用失败 / JSON 解析失败 → 走本地降级。

### 4.2 system 提示词要点

- 角色：高考英语仿真题编题教师。
- 只生成自研仿真内容，**不得收录真题原文、真题选项或真题解析**。
- 英文短文 120–180 词，蓝思难度贴近高考阅读，句子长短交错。
- 每个目标词在文中**只出现一次**，且必须出现在挖空位置。
- 干扰项必须同词性、同主题、拼写相近或义项易混，不能出现明显荒谬选项。
- 只输出 JSON，不要 Markdown 代码块，不要解释。

### 4.3 JSON 输出结构

```json
{
  "title": "A Small Decision",
  "theme": "校园生活",
  "level": "高考阅读 · 标准",
  "paragraphs": [
    "Last term, our class had to ___ a serious problem: ..."
  ],
  "translation": "上学期，我们班不得不解决一个严重的问题：……",
  "blanks": [
    {
      "no": 1,
      "answer": "address",
      "sense_id": "s_address_v_handle",
      "meaning": "处理、解决（问题）",
      "options": ["address", "access", "assess", "accuse"],
      "reason": "address a problem 是「处理问题」的固定搭配。"
    }
  ]
}
```

校验规则（`Article.parseArticle()`）：

- `paragraphs` 非空且拼接后包含每个 `answer` 对应的 `____`/`___` 占位；
- `blanks.length` 在 3–5 之间；
- 每题 `options.length === 4`，`answer` 必须在 `options` 中；
- `sense_id` 必须能在词库中找到；找不到则把该题标为 `light: true`，回流只走 `practiceQuick`；
- 任一硬校验失败 → 整篇降级，不用半篇残缺内容。

## 五、FSRS 回流规则

| 用户自评 | rating | 精修词（有 sense_id） | 轻量词 |
| --- | --- | --- | --- |
| 认识 | 3 | `Store.reviewSense(sense_id, 3, word)` | `Store.practiceQuick(word, 3)` |
| 犹豫 | 2 | `Store.reviewSense(sense_id, 2, word)` | `Store.practiceQuick(word, 2)` |
| 忘了 | 1 | `Store.reviewSense(sense_id, 1, word)` + 记入错词 | `Store.practiceQuick(word, 1)` |

此外：

- 每空都调用 `Store.reviewFamily(word, rating, 'article')`，让词形网同步受益；
- 作答完成后刷新 `syncStats()` / `renderGrowth()`，首页遗忘预警与通知中心自然读取新状态；
- 文章本身不落库，只保留本次作答结果，避免云端存储膨胀。

> 说明：三档自评比传统「对错」更贴合文章语境——学生可能猜对选项但没真正掌握义项，`犹豫` 会给出更短的复习间隔。

## 六、失败的降级路径

按优先级依次尝试：

1. **在线生成**：`cloud.llm` 可用且返回合法 JSON；
2. **词库句群降级**：从 `CTX_BOOK` 取目标词的 `senses[].example` / `example_zh`，拼成一篇「微文章」——每句就是一个真实语境片段，挖空处用目标词替换，义项 ID 与释义直接来自词库；
3. **本地样例文章**：内置 2 篇通用短文，保证断网时功能仍完整可用。

降级文章在页面上标注「离线语境包」，与 AI 生成内容区分，不欺骗用户。

---

## 七、页面与交互

- 新增独立页面 `s-article`，从背词页顶部入口与首页推荐卡进入。
- 页面状态：`loading → reading → answering → result`。
- `reading`：显示标题、主题、英文短文；目标词高亮；提供「显示中文大意」开关。
- `answering`：逐空作答，选完立即显示该空的义项解释与原文还原。
- `result`：本篇正确率、每个目标词的掌握度变化、FSRS 下次复习时间、「下一篇」按钮。
- 移动端优先：短文不折叠，选项大按钮，避免频繁横向滚动。

## 九、风险与边界

- **内容合规**：所有生成内容必须是自研仿真；提示词和 system 都明确禁止真题原文。
- **成本与配额**：免密钥 LLM 有配额，文章生成做前端轻量缓存（同一组词当天只生成一次），避免重复调用。
- **生成质量**：模型可能输出错义词形或错误释义；解析层做硬校验，校验不过直接降级。
- **隐私**：选词只传词形、义项和主题，不传用户手机号、姓名等身份信息。
