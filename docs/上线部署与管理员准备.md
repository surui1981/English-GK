### 2. 上线前：本地构建与回归

每次改动源码后，按此顺序执行，全部通过才进入发布：

```bash
# 1) 若改了词库/成书数据，先重建对应数据（按需）
python tools/build_context_formal.py

# 2) 重建单文件原型：把 app/ 内联进 prototype/index.html
python tools/build_prototype.py

# 3) 全量回归（16 组，当前合计 554 项，须 0 失败）
for f in tools/test_*.js; do printf "%-34s" "$(basename $f)"; node "$f" 2>&1 | grep -E "结果：" | tail -n 1; done
```

当前 16 组测试覆盖：进度、云服务、今日任务、多轮组卷、A-Z、答题流、定价两档、订单、收官卡、语境版、导航、三本材料、复盘、熟词僻义分层、周报导出、新旧权益重构。
任何一组出现失败，先修复再发布，不要把未通过的版本推上线。

### 3. 提交到 Git

```bash
git status --short                      # 确认改动文件，临时截图不要入库
git add -u && git add tools/test_xxx.js # 新测试文件需显式 add
git commit -m "feat: 本次改动摘要"

# 推送（本机必须绕过预设代理 + 禁用图形凭据助手，否则会挂起）
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY \
  git -C C:/ENGLISH-GK -c credential.helper= -c credential.helper=store push origin main

# 校验远端与本地 HEAD 一致
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY \
  git -C C:/ENGLISH-GK ls-remote origin refs/heads/main
git -C C:/ENGLISH-GK rev-parse HEAD
```

两个 HEAD 相同才算推送成功。完整的环境注意事项见项目根 README 与工作记忆。

### 4. 发布到线上

在 WorkBuddy 中用「发布为应用」能力，沿用同一部署标识，分享链接保持不变：

- action：`deploy`
- directory：`C:/ENGLISH-GK`
- entryHtml：`app/index.html`
- language：`static`
- appName：`拾词高考英语`
- domainPrefix：`shici-english-gk`（**必须复用**，否则会生成新链接，老用户手里的分享码失效）

发布会覆盖同一站点，用户无需换链接。

### 5. 发布后校验（务必带分享码）

```bash
BASE="https://shici-english-gk.app.workbuddy.host"

# 主入口与后台均返回 200
curl -s -o /dev/null -w '%{http_code} %{size_download}\n' --compressed --noproxy '*' "$BASE/?sharecode=MHWZWG6UL4"
curl -s -o /dev/null -w '%{http_code} %{size_download}\n' --compressed --noproxy '*' "$BASE/app/admin/index.html?sharecode=MHWZWG6UL4"

# 抽查本轮新功能是否上线（示例：新两档文案）
curl -s --compressed --noproxy '*' "$BASE/app/js/app.js?sharecode=MHWZWG6UL4" | grep -c '资料 + 云端账号 + 全部分析'
curl -s --compressed --noproxy '*' "$BASE/app/index.html?sharecode=MHWZWG6UL4" | grep -c 'materials'
```

要点：
- 加 `--compressed --noproxy '*'`（本机代理环境变量会干扰）；
- 每个静态资源 URL 都要带 `sharecode=MHWZWG6UL4`；
- 关键文案/函数命中数应 ≥1；若为 0，先确认是不是漏带分享码，再判断是否真的没更新。

### 6. 手机端验收

用手机浏览器打开主入口链接，依次验证：首页加载 → 游客能做题 → 手机号验证码登录 → 兑换码兑换 → 支付弹窗两档价格 → 管理后台能进。云端登录/兑换依赖线上域名，本地无法完整模拟，必须在这一步做真实链路验收。

## 第二部分 · 管理员后期需要什么准备

管理员负责的是「云端能不能正常跑、钱和码怎么发、数据出事怎么办」。应用代码已实现后台能力，下面是要人来做准备和决策的部分。

### 1. 云服务开通与配置（技术准备，一次性）

应用依赖 WorkBuddy 云服务（Auth + Database），前端配置已写在 `app/js/config.js`：

- `endpoint`：`https://shici-english-gk.app.workbuddy.host`
- `oauthRelayBaseUrl`：WorkBuddy 的 OAuth 中转
- `publishableKey`：`wbpk_...`（可公开，不含密钥，无需保密）

管理员需要在云控制台确认：

| 准备项 | 说明 | 缺失后果 |
| --- | --- | --- |
| 数据表建好 | `learning_state`、`entitlements`、`admin_roles`、`redeem_batches`、`redeem_codes` 五张表 | 报错「云端数据表尚未就绪」（42P01），学习状态与权益无法保存 |
| RLS 策略 | 各表按 owner-only 配置；`redeem_codes` 不开放 SELECT，只走 `SECURITY DEFINER` RPC | 数据越权或兑换码被直接读取 |
| RPC 函数 | `redeem_code`、`my_redeem_code`、`is_admin`、`create_batch`、`admin_stats`、`admin_list_codes`、`admin_list_batches`、`admin_void_code`、`apply_full_entitlement`、`bootstrap_first_admin` | 后台与兑换功能直接不可用 |
| 短信验证码额度 | 手机号登录走 `sendOtp` / `verifyOtp`，需云侧开通短信能力并充值额度 | 用户与管理员都收不到验证码，无法登录 |
| 微信 OAuth | 微信登录走 `signInWithOAuth`，回调地址为站点根 `location.origin`；需在开放平台配置授权回调域名 | 微信按钮点击后回调失败 |
| 域名白名单 | 线上域名需加入云服务的允许来源 | 浏览器端 SDK 请求被拒 |

> 这些是云端控制台配置，不在代码仓库里；代码里只放可公开的 publishableKey。**任何长期密钥都不要写进前端或仓库。**

### 2. 首位管理员自举（最重要、只有一次机会）

后台没有预设管理员账号，采用「首登自举」：

1. 管理员用**指定手机号**打开管理后台链接，短信验证码登录；
2. 系统检测 `admin_roles` 为空 → 该账号通过 `bootstrap_first_admin()` 自动成为首位管理员（用咨询锁防并发抢注）；
3. 之后任何账号再登录都不会自动获得管理员权限。

**必须提前决定的事**：

- 由谁来当第一个管理员？请用团队**稳定持有、不会弃用**的手机号（不是临时号码、不是员工私人可能离职的号）。
- 自举窗口很短——上线后应第一时间由指定人登录后台完成自举，避免被无关用户抢先。
- 自举完成后，在 `admin_roles` 里登记备用管理员，避免单点依赖（如需第二管理员，走云控制台按同等权限写入白名单）。

### 3. 兑换码发放（对应 ¥9.9 全包权益）

当前真实支付尚未接入（支付弹窗是演示流程），**全包权益实际靠兑换码发放**。后台已具备完整能力，管理员日常要做的：

- **生成批次**：填批次名称、数量（1–500）、备注 → 生成后页面会列出全部码，此时**必须立即复制保存**，离开页面不再明文展示。
- **发放**：把码发给已注册用户；用户在「我的 → 兑换」输入即可开通全包（一码一号，终身绑定该账号）。
- **查询与筛选**：按未使用 / 已兑换 / 已作废筛选，查看批次、绑定手机号尾号、兑换时间。
- **作废**：误发或异常码可作废，**不可撤销**，操作前确认。
- **导出 CSV**：当前筛选结果为 CSV（含 BOM，Excel 可直接打开），用于对账与归档。

发放策略建议：
- 一笔兑换码对应一份全包权益，按实际收款人数生成，不要超发；
- 批次备注写清渠道/日期/收款批次，便于事后追溯；
- 定期导出 CSV 留档，作为发货凭证。

### 4. 权益模型一致性（新两档，务必对齐）

2026-11-22 起权益分两档，管理员对外说明必须与系统一致：

| 档位 | 价格 | 发放什么 |
| --- | --- | --- |
| 四本资料包 | ¥2.9 | 仅四本资料下载（`materials` 权益），**不含**云端与任何分析 |
| 全包 | ¥9.9 | 资料包 + 云端账号服务 + 全部分析（`all` 权益）；兑换码发的就是这一档 |

- 兑换码兑换的是**全包**，不是资料包。
- 基础学习数据（时长/新学/正确率/打卡/柱状图/热力图）对游客永久免费，不设付费墙。
- 深度归因、下周计划、报告导出、FSRS 算法统计统一要求全包。
- 见 README 7.1 与 `tools/test_pricing_v2.js`。

### 5. 日常运维与风险边界

- **数据备份**：定期导出 `learning_state` / `entitlements` 快照与兑换码 CSV；云服务是权威数据源，本地只是离线暂存。
- **订单凭证**：支付/兑换后生成订单记录（保存在「我的 → 我的订单」），可随时下载凭证；管理员应保留兑换发放的 CSV 对账。
- **登录故障**：用户收不到验证码 → 先查短信额度；微信登录失败 → 查 OAuth 回调域名；数据读不到 → 查 RLS 与表就绪。
- **合规红线**：应用内与文档均标注「不含真题与教材原文，例句为仿真语境」；不得宣称真题命中或虚假提分。
- **价格承诺**：一次买断、无续费、无划线价、最高价 ¥9.9 不因新功能变质；新增能力若超出全包范围需重新评估，不得悄悄加价。
- **付费接入**：真实微信支付尚未接入，正式商用前需完成支付网关与回调验签，避免只靠人工发码长期运转。
